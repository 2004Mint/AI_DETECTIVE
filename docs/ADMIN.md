# AI 造梦事务所 · 内容管理后台

> 访问地址：`/admin`（本地 `http://localhost:5173/admin`，构建后同一路径）
>
> **定位：纯前端内容编辑台。** 项目没有服务端，后台不会写服务器，也不会直接改仓库文件；
> 它把作品 / 参数整理好，导出成 `works.ts`、`site.ts` 和素材 ZIP，你提交到代码库后线上才生效。

---

## 一、进入后台

```
http://localhost:5173/admin
```

- 没有登录（没有后端，登录只是摆设）；
- 数据存在**当前浏览器**的 localStorage + IndexedDB 里；
- 换电脑、清缓存、换浏览器都会看不到之前的草稿，所以录完请及时导出。

---

## 二、录入一件作品

1. **作品管理 → 新增作品**
2. 填标题、选分类；ID 会自动生成（可改，但要唯一）
3. 把图片拖进「封面图片」区域（或点「选择图片」）
   - 会自动压缩成 WebP，最长边 1600px；
   - 保存后自动命名为 `<作品ID>.webp`
4. 补上简介、Prompt、AI 工具、创作者、票数（都可以留空，之后再加）
5. 点「保存」

表格里状态会显示：

| 状态 | 含义 |
| --- | --- |
| **新图待导出** | 图片已存在本机 IndexedDB，还没进仓库 |
| 已配图 | 用的是仓库里已有的图片文件 |
| 缺图 | 没有封面，前台会显示「待补充作品图片」 |

音乐作品会出现「音乐试听」区块，上传 mp3 / m4a 即可；文字作品会出现「作品正文」。

---

## 三、导出并发布

进入 **导出发布**：

| 按钮 | 产物 | 放哪里 |
| --- | --- | --- |
| 下载 works.ts | 作品数据源码 | 覆盖 `src/data/dream/works.ts` |
| 下载 site.ts | 站点文案参数 | 覆盖 `src/data/dream/site.ts` |
| 下载素材 ZIP | `works/*.webp` + `audio/*` + README | 解压后把 `works/`、`audio/` 合并进 `public/dream/` |

然后在本机执行：

```bash
npm run check:dream   # 自检：缺图 / id 重复 / 分类写错
npm run dev           # 预览确认
npm run build         # 发布
```

> ZIP 只包含「后台新上传」的素材，引用仓库已有文件的作品不会重复打包；
> 导出面板会提示有多少个文件已在仓库里。

---

## 四、改站点参数

**站点参数** 里可以改：

- 首页标题（同时用于顶栏品牌）
- 首页副标题
- 页脚社团署名
- 页脚补充说明

保存后同样走「导出发布 → 下载 site.ts」。

---

## 五、数据与清理

| 内容 | 位置 | 说明 |
| --- | --- | --- |
| 作品草稿 / 站点参数 | localStorage `ai-dream-studio:admin:v1` | 体积小，随手保存 |
| 上传的图片、音频 | IndexedDB `ai-dream-studio-assets` / `assets` | 存 Blob，不受 localStorage 5MB 限制 |

**重新从源码导入**（导出发布页底部）会清空本机草稿与已上传素材，
重新读取仓库里的 `works.ts` / `site.ts`——适合「导出完、提交完，重新开始」的场景。

---

## 六、注意事项

1. **不是线上 CMS**：没有服务端、没有多用户、没有权限控制。别把它部署成公开编辑入口；
   如果以后要多人协作，需要接后端（作品表 + 素材上传接口 + 登录）。
2. 图片会自动压成 WebP，想保留原图请另外存档。
3. 删除作品会同时删除本机对应的图片/音频；仓库里的文件不会被删，需要手动清理。
4. 导出的 `works.ts` 会保留作品上的所有字段（含 `tag` / `featured` 等当前页面未展示的可选字段）。
